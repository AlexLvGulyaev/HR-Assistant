## 🎯 2. Назначение

**Бизнес-цель:** Автоматизация первичной обработки резюме и подбора вакансий.

**Решаемая проблема:**
- Медленная обработка резюме (10-15 минут на резюме)
- Ручное извлечение данных из резюме
- Отсутствие автоматизированного matching кандидатов с вакансиями
- Ограниченные форматы ввода резюме

**Целевая аудитория:**
- HR-специалисты
- Рекрутеры
- Кандидаты (через Telegram-бот)

## 🧪 9. Экспериментальный ML-контур

**⚠️ Важно:** Экспериментальный ML-контур НЕ используется в production. Он предназначен для исследования и улучшения качества системы.

### Назначение

Экспериментальный ML-контур обеспечивает непрерывное развитие качества системы за счёт:
1. Prompt Evaluation (A/B-тестирование промптов)
2. Fine-tuning (обучение LoRA-адаптеров)
3. Runtime Smoke Validation (тестирование моделей)

### Workflow

| Workflow | Узлы | Назначение | Контур |
|----------|------|-----------|--------|
| **HRA Prompt Evaluation Experiment** | ~50 | A/B-тестирование промптов | Experimental |
| **HR Processing Worker - Multi Provider Test** | 54 | Smoke validation LoRA-моделей | Experimental |

**Важно:** `HR Processing Worker - Multi Provider Test` — это инженерный стенд, НЕ production workflow.

### AI-модели (Experimental)

| Модель | Назначение | Workflow | Параметры |
|--------|-----------|----------|-----------|
| **Qwen/Qwen2.5-1.5B-Instruct** | Base model для Fine-tuning | Multi Provider Test | LoRA adapter |
| **Qwen + LoRA adapter** | Fine-tuned model | Multi Provider Test | Temperature: 0.2 |

### LLM-провайдеры (Experimental)

| Провайдер | Endpoint | Назначение | Authentication |
|-----------|----------|-----------|----------------|
| **RunPod** | RunPod proxy URL | Smoke validation LoRA-моделей | None (proxy endpoint) |

### База данных (Experimental)

**⚠️ Изолирована от production:**

| Таблица | Назначение |
|---------|-----------|
| `eval_prompt_datasets` | Версии датасетов |
| `eval_prompt_cases` | Тестовые кейсы |
| `eval_prompt_case_vacancies` | Вакансии с reference-разметкой |
| `eval_prompt_experiments` | Определения экспериментов |
| `eval_prompt_runs` | Запуски экспериментов |
| `eval_prompt_results` | Результаты выполнения |

### Результаты экспериментов

| Метрика | Base Qwen | Qwen + LoRA | GPT-4o-mini (baseline) |
|---------|-----------|-------------|------------------------|
| Offline Validation | ✅ Baseline | ✅ Improved (Exp 002) | Reference |
| Runtime Positive Test | ✅ Pass | ✅ Pass | N/A |
| Runtime Negative Test | ✅ Pass | ❌ Failed (Exp 002) → ✅ Pass (Exp 003, после hard negatives в teacher dataset) | N/A |
| External validation (Exp 004) | — | ✅ 0.931 vs GPT-4o-mini 0.925 | 0.925 |

**Вывод (после Experiments 001–004):** LoRA — рабочий on-premise / edge кандидат; production-контур остаётся за GPT-4o-mini. LoRA не применяется в production.

## 🔍 15. Диагностика и устранение неполадок

### Типовые инциденты

#### Инцидент 1: Обработка зависла

**Симптомы:**
- Записи в статусе `processing_started` > 5 минут
- Кандидаты не получают ответ

**Диагностика:**
```sql
SELECT COUNT(*) FROM candidate_inputs
WHERE processing_status = 'processing_started'
  AND created_at < NOW() - INTERVAL '5 minutes';
```

**Решение:**
1. Проверить Watchdog workflow
2. Сбросить зависшие записи вручную:
```sql
UPDATE candidate_inputs
SET processing_status = 'prepared'
WHERE processing_status = 'processing_started'
  AND created_at < NOW() - INTERVAL '5 minutes';
```

---

#### Инцидент 2: Telegram Bot недоступен

**Симптомы:**
- Webhook не работает
- Кандидаты не могут отправить резюме

**Диагностика:**
```bash
curl -X GET "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/getWebhookInfo"
```

**Решение:**
1. Проверить WEBHOOK_URL
2. Переустановить webhook
3. Проверить SSL сертификат

---

#### Инцидент 3: OpenAI API недоступен

**Симптомы:**
- Ошибки извлечения данных
- Ошибки matching

**Диагностика:**
- Проверить https://status.openai.com
- Проверить логи n8n (узлы OpenAI)

**Решение:**
1. Ждать восстановления API
2. Увеличить retry attempts
3. Сообщить пользователям о задержке

## 🔄 16. Процедуры управления жизненным циклом

### Развёртывание

**Процедура:**
1. Создать бэкап БД
2. Остановить n8n workflows
3. Применить миграции БД
4. Обновить workflows
5. Запустить n8n workflows
6. Проверить healthcheck

**Откат:**
1. Восстановить БД из бэкапа
2. Откатить workflows к предыдущей версии
3. Перезапустить n8n

---

### Обновление

**Частота:**
- Security updates: немедленно
- Feature updates: по расписанию (раз в месяц)
- Dependency updates: по необходимости

**Процедура:**
1. Тестирование в staging
2. Code review
3. Деплой в production
4. Smoke tests
5. Мониторинг

---

### Удаление

**Процедура вывода из эксплуатации:**
1. Уведомить пользователей за 30 дней
2. Остановить приём новых резюме
3. Экспортировать данные
4. Удалить workflows
5. Удалить БД
6. Удалить инфраструктуру
