## 12. Наблюдения для narrative blueprint

1. **Dataset engineering > adapter tuning.** Гиперпараметры LoRA неизменны с Experiment 002/003 (`r=16`, `alpha=32`, `dropout=0.05`, 7 target modules). Рост качества (`decision_accuracy` 0.67 → 0.80, FNR снижен) достигнут добавлением positives/borderlines, а не тюнингом адаптера. *Источник:* `best_adapter/adapter_config.json`, `configs/experiment_004.yaml` (контекст), `generation_test/generation_test_report.json`.

2. **Best checkpoint selection по eval_loss корректен.** Минимум `eval_loss` 0.3273 приходится на `checkpoint-87` (эпоха 3); далее loss растёт до 0.3722 на эпохе 5. *Источник:* `trainer_state.json` → `log_history`; `training_report.json` → `best_metric`, `best_checkpoint`.

3. **Recall восстановлен, precision сохранена.** Generation test decision accuracy = 0.800, runtime smoke 7/7 без unexpected matches, FNR = 0.0 на GPT comparison v2. Это указывает, что добавление positives/borderlines вернуло recall без возврата false positives. *Источник:* `generation_test/generation_test_report.json`, `runtime_smoke_report.json`, `gpt_comparison_report_v2.json`.

4. **Внешняя валидация показывает сильную генерализацию, но не production parity.** `external_validation_report.json`: decision accuracy 0.931 vs GPT-4o-mini 0.941 на 102 записях. Однако MAE 19.6 vs 6.2 и FNR 13.6% vs 4.5% показывают, что LoRA более консервативна и хуже калибрована. *Источник:* `external_validation_report.json` → `lora_summary`, `gpt_summary`.

5. **Production bug: truncation + HTTP 422.** GPT comparison v1 дал `valid_json_rate` 0.867 из-за `max_tokens=300`; два кейса (`HRA-EVAL-V2-000010` и `HRA-EVAL-V2-000211` на вакансии «Специалист по разметке данных») вернули HTTP 422. После увеличения `max_tokens` до 512 и graceful fallback — 100% valid JSON. *Источник:* `gpt_comparison_report.json`, `gpt_comparison_report_v2.json`, `OPERATION_LOG.md` → Post-VPS fix.

6. **Latency optimization даёт production-viable скорость.** transformers_fp16 p50 ~9.5 s; vllm_fp16 p50 ~2.2 s; повторные прогоны vLLM на 102 записях показывают p50 ~1.7 с и p95 ~2.1 с. *Источник:* `engine_benchmark_report.json`, `engine_benchmark_report_vllm.json`, `external_validation_repeated_report.json`.

7. **Generate — доминирующий bottleneck.** Stage profile: generate занимает ~9.9 с из ~9.9 с total (p50), >99% времени. *Источник:* `latency_profile_report.json` → `stage_summary`.

8. **Test perplexity не отражает качество решений.** Eval loss base_qwen = 7.8141, best_lora = 7.8079 — почти идентичны, тогда как decision accuracy выросла с 0.333 до 0.800. *Источник:* `test_evaluation/test_metrics.json`, `generation_test/generation_test_report.json`.

9. **Повторяемость vLLM-предсказаний стабильна.** 3 повторных прогона external validation дали decision accuracy LoRA 0.931 (min=max=avg), MAE ~19.53, p50 ~1687 ms. *Источник:* `external_validation_repeated_report.json`.

10. **Hard-negative качество остаётся слепым пятном external validation.** В наборе 102 записей нет явной категории `hard_negative`; по PROJECT_STATE только ~17.6% hard-negative-like записей. Для следующего цикла требуется stratified production smoke set. *Источник:* `external_validation_report.json` → `results` case_type distribution; `PROJECT_STATE.md` → Known Issues.
